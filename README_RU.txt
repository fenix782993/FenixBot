FENIX ONLINE BOT 2.0
====================

Полная сборка проекта на основе исходного FenixBot-main. Существующие assets,
регистрация, рефералы, подписка, медиа-заявки, выплаты, публикации, админ-панель
и управление составом сохранены.

НОВОЕ В 2.0
-----------
1. Кабинет игрока:
   - отдельные экраны заявок, уведомлений, достижений, статистики и поддержки;
   - обращения хранятся в БД, переписка сохраняется;
   - администрация получает новые обращения и отвечает через кнопки;
   - решения по медиазаявкам и выплатам создают уведомления.
2. Кабинет медиапартнёра:
   - отдельные кнопки статистики видео, канала, календаря и истории выплат;
   - активность и выплаты вынесены в отдельные экраны;
   - подтверждённые просмотры из проверки выплаты попадают в статистику.
3. Навигация:
   - меню и экраны по возможности редактируют существующее сообщение;
   - у callback-экранов есть быстрый ответ Telegram;
   - кнопки возврата в кабинет и главное меню.
4. Скорость:
   - добавлен пул соединений psycopg_pool для Neon/PostgreSQL;
   - настройки кэшируются на 15 секунд;
   - массовая рассылка выполняется в фоновой задаче с ограниченной параллельностью;
   - добавлена зависимость psycopg-pool.
5. Публикации:
   - авторский текст остаётся обычным;
   - внизу отдельной цитатой оформляется фирменная подпись FENIX ONLINE.

ВАЖНО О СКОРОСТИ
----------------
Пул убирает повторное создание TLS-соединения для каждого SQL-запроса.
Существующие DB-методы проекта синхронные, поэтому это не полная миграция
на async SQL. Для минимизации риска сохранена совместимость с текущими
обработчиками. После деплоя нужно проверить задержки на реальном Neon.

НОВЫЕ ТАБЛИЦЫ
-------------
При старте автоматически создаются:
- tickets и ticket_messages — обращения и переписка;
- notifications — уведомления;
- achievements — достижения;
- media_video_stats — подтверждённые просмотры.

Существующие таблицы не удаляются и не пересоздаются.

RENDER
------
В render.yaml настроен Web Service, так как бот поднимает HTTP endpoint /health.
Переменные окружения:
- BOT_TOKEN — токен Telegram-бота;
- ADMIN_IDS — Telegram ID владельцев/первичных администраторов через запятую;
- CHANNEL_ID — числовой ID обязательного канала;
- CHANNEL_URL — ссылка приглашения в канал;
- DATABASE_URL — pooled connection string Neon PostgreSQL (хост с -pooler);
- DATABASE_PATH — запасной путь SQLite, если DATABASE_URL не задан.

Не добавляй .env в GitHub. Не публикуй BOT_TOKEN и DATABASE_URL.

ДЕПЛОЙ
------
1. Сделай резервную копию текущего GitHub-репозитория.
2. Замени файлы проекта содержимым этого архива.
3. Сохрани секреты в Render Environment; не коммить .env.
4. Убедись, что DATABASE_URL указывает на Neon pooled endpoint и содержит sslmode=require.
5. Запусти Deploy.
6. Проверь /health, затем /start, регистрацию, кабинет, поддержку, медиараздел
   и тестовую публикацию в закрытом тестовом канале.

ПРОВЕРКА
--------
Локально выполнены:
- компиляция bot.py и db.py;
- создание схемы SQLite;

МАГАЗИН FENIX / FNZ
-------------------
- Mini App: раздел «Ещё» -> «Магазин FENIX» и «Кошелёк FNZ».
- Владелец задаёт курс FNZ за рубль и цены товаров в «Админ-панель» -> «Магазин и платежи».
- Ручные платежи: Сбербанк / Т-Банк, номер +7 906 785-38-60. Администратор подтверждает платёж, после чего FNZ начисляются на баланс.
- Robokassa: добавьте в Render Environment ROBOKASSA_MERCHANT_LOGIN, ROBOKASSA_PASSWORD1, ROBOKASSA_PASSWORD2. На стороне Robokassa укажите ResultURL:
  https://fenixbot-vyqo.onrender.com/api/payments/robokassa/result
  Метод ResultURL — POST. Для теста ROBOKASSA_TEST_MODE=1; после проверки переключите на 0.
- Robokassa callback сверяет подпись, сумму и номер счёта; повторное начисление предотвращается уникальной записью кошелька.
- Покупка списывает FNZ и создаёт заказ со статусом «Ожидает выдачи». Администратор переводит заказ в обработку и отмечает выдачу.
- Конструктор номера: база 700 FNZ; три одинаковые цифры +100%, три одинаковые буквы +150%, одинаковые цифры региона +20%. Бонусы складываются, поэтому А777АА 77 стоит 2 590 FNZ.
- BMW M3, чип тюнинга III и военный билет требуют указать цену в админ-панели до покупки.

ВАЖНО О ВЫДАЧЕ НА СЕРВЕРЕ
-------------------------
Сейчас магазин создаёт и учитывает заказы, но автоматическая выдача предметов в SA:MP не включена. Для неё необходим доступ к базе данных игровых аккаунтов/автомобилей или документированный серверный API. Пароль игрового аккаунта нельзя сверять с паролем Telegram-кабинета; алгоритм хеширования и схема базы сервера должны быть подтверждены отдельно.
